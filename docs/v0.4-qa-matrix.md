# RustShot v0.4.0 — Manual Windows 11 performance and DPI QA

CI passes only prove compilation, unit tests, and portable packaging. Measurements below must be collected on a real Windows 11 desktop. **Targets are not actual readings.**

## Required desktop matrix

| Case | Test | Pass condition |
|---|---|---|
| Laptop integrated display | 1920×1080, 125% scale | Screenshot, selection and annotations align |
| Two displays | 1080p left at 100%; 4K primary at 150% | Accurate negative X and toolbar handles on either screen |
| Three displays | Primary + monitors positioned above and left | Signed X/Y clipping and dragging operate |
| DPI change | Change scaling while overlay is open | Overlay safely closes; next screenshot uses fresh geometry |
| Hotkey | 100 repeated Alt+A, Esc | No crash or new saved images; no zombie overlay |
| Restore focus | From Firefox/VS Code/Explorer, screenshot or cancel | Prior interactive app is reactivated where OS focus rules allow |
| Big screen | 4K/8K resolution | No image truncation, no oversize PNG block |
| Zoom / window | Resize selection across monitor seam | Handles remain aligned; annotations export in chosen crop |
| PNG validity | Open 100 exported PNGs in Paint, ImageMagick or Pillow | All decode and have exactly selected dimensions |
| MIME clipboard | Paste to Paint, Word, browser | BGRA correctly represented as RGB; no blue-red swap |
| Memory | 10h idle, 100 4K captures | No monotonic working set/private bytes/GDI handle leak |
| Load / continuity | Save same full-screen capture repeatedly | No output collision; export works independently of busy clipboard |
| DPI event | Attach/disconnect monitor during overlay | No crash; snapshot state released |
| Protected surface | DRM or excluded windows | System restrictions respected; no bypass claimed |
| Text/mosaic regression | Chinese pinyin, Alt+A, text, mosaic, undo, save | v0.3 functions unaffected |

## Performance targets (P50 / P95 and peak memory)

Record Windows build, display topology, scaling, CPU, GPU, process working set, private bytes, CPU use, GDI/USER objects, EXE version and exact actions. Target idle working set remains 15–35 MiB **only as an engineering target**, not as tested data.

Use Performance Monitor counters:
- \`Process(RustShot)\Private Bytes\`
- \`Process(RustShot)\Working Set - Private\`
- \`Process(RustShot)\% Processor Time\`
- \`Process(RustShot)\Handle Count\`

For deeper GPU/GDI investigation: Windows Performance Recorder / Windows Performance Analyzer (WPR/WPA) or Process Explorer GDI/USER handle columns.

## Architecture expectations

- Captured frame after overlay starts: **one** persistent full-desktop BGRA buffer; no persistent darkened copy.
- PNG encoder peak extra buffer (excluding caller-owned BGRA): about two 64 KiB blocks + one 3×width scanline. PNG remains stored/near-uncompressed.
- No screenshot capture polling while tray is idle.
- The gray overlay is rendered with \`AlphaBlend\`. If it fails on a GPU/driver, report the build and screenshot; do not assume fallback is perfect.
